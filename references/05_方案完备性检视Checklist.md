# 方案完备性检视 Checklist (v2.0)

> [!IMPORTANT]
> **定位与纯前端 Mock Demo 适用性说明：**
> - **本 Checklist 为【维度 4：方案完备性检视】的专项审查标准**。
> - **前端 Mock Demo 检视边界与豁免原则（不校验真实后端生效逻辑）**：
>   1. **豁免项（严禁误判为缺陷）**：
>      - ❌ **真实数据落库与持久化**：页面刷新后新增的 Mock 数据重置，属于 Mock 正常表现，豁免；
>      - ❌ **真实服务端网络与会话异常**：真实网络断网重发、真实 50x 网关熔断、真实 Token 过期 SSO 鉴权流转，豁免；
>      - ❌ **真实分布式异步长任务**：服务端后台队列轮询等依赖真实后端的流程，豁免。
>   2. **纯前端审查重心（代码审查优先 + 前端设计闭环）**：
>      - 🎯 **全链路流程闭环与防悬空**（主流程与关键分支、操作去向、返回逻辑、终态收尾，无死胡同）；
>      - 🎯 **组件与表单全状态覆盖**（默认/聚焦/输入/报错/禁用/只读/半选/加载/空数据/边界）；
>      - 🎯 **前端表单前置校验与防错二次确认**（必填正则校验、失焦即时报错、不可逆操作二次确认）；
>      - 🎯 **交互感知、防重与混合结果反馈**（即时反馈、提交防重、批量混合结果汇总、未保存退出挽留）；
>      - 🎯 **环境自适应与极限尺寸**（表格水平滚动与固定列、长表单弹窗内部滚动且底部操作栏吸底固定）。
> - **批量轻微问题表格化展示规则**：
>   * **触发条件（必须同时满足以下 3 项，缺一不可）**：
>     1. 识别问题**仅属于维度 4（方案完备性检视）**单维度；
>     2. 问题级别**均为 P3 / P4 型**（不含 P2 严重阻塞或高危操作缺失）；
>     3. 问题数量**大于 3 个**（$\ge 4$ 个）。
>   * **展示规范**：以汇总表格集中呈现，表格字段统一为：`页面`、`缺失类型`、`缺失描述`。
> - **定量耗时与规模熔断（Anti-Sloth）**：
>   * **触发阈值**：单文件行数 > 5000 行，或该维度走查耗时累计 > 8 分钟。
>   * **熔断后保底**：基于已检索代码进行核心标记抽检（`loading|empty|catch|show-overflow|confirm`），输出轻量定性结论。
> - **明确不包含界面 UI 视觉还原打尺**（如像素级 Padding/Margin、组件 Radius、Hex 颜色打尺等）。

## 证据类型标签说明（`[S]` / `[R]` / `[I]`）

每条检视项末尾的标签，表示**这条结论需要什么类型的证据**。执行时按标签选采集方式，**不得用低强度证据冒充高强度证据**。

| 标签 | 判据（一句话） | 采集方式 | 未做到时的处理 |
| :--- | :--- | :--- | :--- |
| **`[S]` 静态可判定** | **不打开页面**就能确定「有 / 无」 | 读代码 / DOM 结构，可穷举 | 无（静态扫描天然可穷举） |
| **`[R]` 需真实渲染** | 不打开不行，但**看到真实页面就能判断**，不必操作 | 真实数据填充的截图（正常 / 空 / 异常 / 极值） | 结论降为「中置信」，不得定 P2 |
| **`[I]` 需真实交互** | 看到了仍判断不了，**必须动手**才知道 | 真实点击 / 输入 / 悬停 / 滚动 | 结论强制降为「待验证假设」，不得定 P2、不得让该维度判「完备」 |

**判定口诀**：闭上眼睛，能不能确定答案是「有」还是「没有」？
- 能 → `[S]`
- 不能，但**看一眼**真实页面就能 → `[R]`
- 不能，必须**动手**才知道 → `[I]`

**五条硬约束**：

1. `[S]` 项禁止用「走查时顺手看了一眼」代替静态核查 —— 静态扫描才能穷举（例如「12 个列表页是否都有空态插槽」，在浏览器里无法穷举，读代码一遍即可）。
2. `[R]` 项禁止用「读代码推测渲染效果」代替真实截图 —— 视觉层级、信息密度、溢出排版必须看真实数据填充后的画面。
3. `[I]` 项禁止用「代码里有 `confirm` / `loading`」代替真实操作 —— 存在性不等于有效性（按钮可能被遮罩点不到、弹窗文案可能没说清后果）。
4. **一趟取证可服务多个维度**：一次 `[R]` 截图可同时判维度 1/3/4 的 R 项；一次 `[I]` 交互可同时判维度 1/3/4 的 I 项。禁止按维度重复打开同一页面。
5. `[I]` 项未实际操作的，必须按原因码申报未覆盖：`NO_DATA`（造不出数据）/ `NO_PERM`（无低权限账号）/ `OVER_BUDGET`（超出范围已确认）/ `ENV_LIMIT`（环境限制）。禁止静默跳过。

## 一、 业务流程与全状态矩阵 (Flow & State Matrix)

### 1. 全链路流程闭环与分支覆盖 (Flow Completeness & Branch Coverage)
- [ ] **主流程与关键分支覆盖** `[I]`: 
  - 是否不仅设计了正向“创建/配置成功”链路，也覆盖了**取消、上一步、重选、条件分支（如选择不同类型展开不同表单项）**等分支逻辑。
  - *判定标准*：仅存在单一成功流程，缺少明确的取消或关键分支流转 $\rightarrow$ 流程不完备。
- [ ] **防悬空交互节点 (No Dangling Nodes)** `[S]`: 
  - 界面上所有按钮、图标、操作列链接均有明确行为去向。
  - *判定标准*：**严禁存在点击无任何响应的空函数（`@click=""`）、未绑路由的死链接（`href="#"`）或操作无终态收尾的死胡同**。
- [ ] **明确的返回与收尾机制** `[I]`: 抽屉/弹窗在完成或取消后是否有明确的关闭与列表刷新逻辑；多步骤向导在每一步均有明确的“上一步/下一步/取消”行动点。

### 2. 组件与表单细化状态覆盖 (Component & Form States)
- [ ] **表单阶段状态矩阵** `[I]`:
  - 输入框/选择器是否具备完整的交互阶段状态：**默认态 (Default) $\rightarrow$ 获得焦点 (Focus) $\rightarrow$ 正在输入 $\rightarrow$ 失焦报错 (Invalid/Error) $\rightarrow$ 禁用 (Disabled) $\rightarrow$ 只读 (Readonly)**。
- [ ] **复杂组件细化状态** `[I]`:
  - 树形选择、表格多选在部分选中时是否正确配置 **半选态 (`indeterminate`)**。
  - 标签、Tab、分段控制器是否有清晰的 **选中态 (`active/selected`)** 与禁用态。
- [ ] **合理默认值与兜底** `[R]`:
  - 筛选项、下拉菜单、日期范围等是否均有合理的默认选中值（如默认“最近 7 天”或“全部”），避免进入页面时首屏呈现不确定的未配置状态。

### 3. 空白 / 零数据态 (Zero / Empty States)
- [ ] **初始化无数据** `[S+R]`: 模块初次使用无数据时，是否配置 `<template #empty>` 插槽、清晰的无数据图文说明及引导创建的“去新建”行动按钮。
- [ ] **筛选/搜索无结果** `[I]`: 用户输入无效关键词或组合筛选无结果时，提示“未找到相关结果”，并提供“重置/清空筛选条件”快捷操作。
- [ ] **列表清空态** `[I]`: 数据被全部删除清空后，能优雅转入空白引导态，而非留下空表头骨架。

### 4. 加载中状态 (Loading States)
- [ ] **首屏骨架屏 (Skeleton)** `[S]`: 首屏大盘图表或复杂大列表数据加载时，是否预留骨架屏结构，避免页面白屏骤闪与布局跳动。
- [ ] **局部 Spin/Loading** `[I]`: 表格翻页、树展开、抽屉内容切换、Tab 切换等局部刷新时是否有明确的局部 Loading 遮罩。

### 5. 极端临界数据与边界 (Boundary & Edge Data States)
- [ ] **文本超长溢出截断** `[I]`: 用户名、规则/策略名称、长 URL 或 IP 范围超长时，是否配置省略号截断（`show-overflow-tooltip` / `text-overflow: ellipsis`）并在鼠标悬浮时展示完整 Tooltip。
- [ ] **海量数据/分页终态** `[S+R]`: 表格数据量较大时配置分页（Pagination）或虚拟滚动；分页翻至末尾时有“已加载全部”提示。
- [ ] **极限数值排版** `[R]`: 极大值（如 `999,999+`）、浮点数（保留合理小数位）及物理单位（KB/MB/GB/bps）换算排版正常，无折行错位。

## 二、 交互细节、防错与容错机制 (Interaction & Safeguards)

### 6. 高危防错与二次确认 (Confirmation & Safety)
- [ ] **高危操作强模态阻断** `[S+I]`: 删除、批量解封、重启服务、覆盖/清空配置等不可逆操作，必须配置强模态二次确认弹窗（`ElMessageBox.confirm`）。
- [ ] **风险后果清晰告知** `[I]`: 二次确认弹窗中必须明确告知操作后果（如：“删除后将无法恢复，关联的 3 条策略也将失效”）。
- [ ] **极高风险二次输入防误触** `[I]`: 极高危操作（如清空整个规则库、解绑核心租户）要求用户手动输入指定确认词（如输入 `DELETE`）。

### 7. 表单前置校验与即时报错 (Form Validation)
- [ ] **实时失焦行内报错** `[I]`: 输入框失焦（Blur）时实时触发必填与格式正则校验（如 IP、域名、Port、CIDR、邮箱），并在组件下方展示行内红色报错文本。
- [ ] **提交阻断与聚焦定位** `[I]`: 表单校验不通过时阻断提交，并自动平滑滚动并聚焦到首个报错输入项。
- [ ] **格式自动纠错清洗** `[I]`: 用户粘贴前后带空格的字符串时，前端自动清洗外侧空格（如 `v-model.trim`）。

### 8. 操作感知反馈、防重与混合结果 (Feedback & Anti-duplicate)
- [ ] **操作即时感知反馈** `[I]`: 点击“保存/提交/重置”后，界面有明确的前端反馈（如顶部弹出 `ElMessage.success` 成功 Toast、弹窗自动平滑关闭、列表自动追加/更新 Mock 数据）。
- [ ] **防重复提交 (Debounce)** `[I]`: 提交按钮在点击发起后立即进入 `:loading="isSubmitting"` 或置灰禁用状态，防止用户快速连击造成重复触发表单。
- [ ] **批量操作混合结果结构化反馈** `[I]`: 批量删除/批量下发时，若存在部分成功、部分失败，是否设计了结构化的结果汇总反馈（如：“成功 8 条，失败 2 条 [查看失败原因]”），而非单一的泛化 Toast。

### 9. 中断恢复与未保存退出挽留 (Draft & Session Protection)
- [ ] **未保存退出防误关** `[I]`: 复杂多步骤表单/配置向导填写中途点击“取消”、点击弹窗遮罩层（Mask）或切换页面时，必须弹出“确定离开？未保存的内容将丢失”的二次挽留确认。

## 三、 权限与角色场景 (Permissions & Roles)

### 10. 静态无权限场景与视图隔离 (Permission Presentation)
- [ ] **无权限操作入口置灰/说明** `[I]`: 无权限操作的按钮提供置灰态并配置 Tooltip 悬浮说明（如：“需要超级管理员权限”），或遵循按需隐藏策略。
- [ ] **无权限页面引导** `[I]`: 跨模块直接访问未授权视图时，展示 403 缺省页并提供“返回上一页”或“返回首页”入口。

### 11. 跨角色视图与数据脱敏 (Roles & Data Masking)
- [ ] **角色视图适配** `[I]`: 运维角色（关注排查与明细）与管理角色（关注大盘与趋势）的默认视图合理隔离。
- [ ] **敏感数据脱敏** `[S+R]`: 密钥、Token、密码、手机号等敏感信息在界面上提供星号 `***` 脱敏展示及“点击查看（需确认）”交互。

## 四、 环境与极限尺寸适配 (Environment & Layout Boundary)

### 12. 极限尺寸、弹窗吸底与溢出适配 (Layout & Extreme Dimensions)
- [ ] **长表单弹窗内部滚动与按钮吸底 (Sticky Footer)** `[R]`: 
  - 弹窗/抽屉表单项超长撑满屏幕高度时，**弹窗主体内部必须配置纵向滚动条（`overflow-y: auto`），底部操作按钮栏必须保持吸底固定**，确保“确定/取消”按钮始终可见可点。
- [ ] **表格横向滚动与固定列 (Fixed Columns)** `[R]`: 
  - 复杂表格列数超多时，表格容器配置水平滚动条，且关键标识列（如“规则名称/ID”）与“操作列”配置固定吸附（`fixed="left/right"`），避免滚动后丢失上下文。
- [ ] **屏幕分辨率与挤压适配** `[R]`: 
  - 在 1920x1080、1440x900、1280x800 等不同分辨率下，页面核心模块无重叠，左右侧分栏比例自适应合理。
- [ ] **多语言长字符空间** `[R]`: 按钮、标签、表头预留 30%-50% 字符扩展空间，避免在英文/多语言环境下文字溢出折行撑破容器。
