# 安全产品设计检视 (Design Review) Skill 包

本仓库旨在通过 AI 代理（Agent）标准化、专业化地对安全产品界面进行深度设计检视，确保设计方案不仅符合规范，更能体现产品的顶层体验愿景。

## 价值主张
- **专业深度**: 结合 10 年以上资深体验专家视角，识别隐藏的交互漏洞与心智模型偏差。
- **高维对齐**: 确保每一个设计细节都符合产品的“品牌灵魂”与“体验愿景”。
- **闭环产出**: 生成带有截图批注、问题定级（P1-P4）以及 To-Be 改进方案的专业 HTML 报告。
- **降本增效**: 通过自动化脚本实现毫秒级精准坐标定位与批注，告别手动绘图。

## 包含内容
- `SKILL.md`: **核心指令集**。定义了 AI Agent 的角色、四大检视维度执行逻辑、评分规则及输出格式要求。
- `references/`: **知识库**。
  - `01_体验目标制定.md`: 体验目标及宏大/务实双版本剧本制定规范。
  - `02_设计检视Checklist.md`: 检视子维度快速匹配指南与通用/特定场景 Checklist 准则。
  - `04_SASE体验愿景.md`: 通用体验愿景基准与四大核心场景理念映射矩阵。
  - `05_HTML检视报告模板.html`: 报告生成模板。
  - `06_方案完备性检视Checklist.md`: 方案完备性与全状态矩阵（正常/空白/加载/报错/极端边界）专项 Checklists。
- `Reports/`: **产出目录**。生成的 HTML 报告及 `assets` 截图资源存放地。
- `scripts/`: **自动化工具箱**。
  - `auto_annotate.py`: 图片标注底层画笔，在浏览器走查模式下对截图进行框选、等级标签批注，落图至 `Reports/assets`。
  - `report_builder.py`: 通用报告生成器，读取问题 JSON（按 `configs/_template_issues.json` 格式）并结合模板生成结构化 HTML 检视报告，内置评分计算、枚举白名单校验与准出自检。

## 🎯 四大检视维度与执行顺序规程
- **维度选择式执行（默认分开）**：默认不自动全量检视，启动时输出维度选择卡片（说明各维度范围与意图）并给出初步判断，由用户确认要检视的维度；只有用户明确「全量」才同时执行全部 4 个维度。
- **执行顺序（以 `EXECUTION_FLOW.md` 为准，按证据采集方式分组，先动态后静态）**：
  1. **第一阶段 · 动态浏览器走查（维度 1 与维度 3，仅同时选中时合并）**：走主任务剧本与交互 Checklist，共用浏览器会话采集证据。
  2. **第二阶段 · 方案级高维审视（维度 2，独立）**：产品专家视角审视方案与愿景契合度。
  3. **第三阶段 · 静态代码扫描（维度 4）**：扫描全状态矩阵与异常/边界态完备性。
- **报告生成**: 生成包含截图批注、严格 P1-P4 定级（最下方附带业务后果判定表）与四维定性结论的专业报告。

## 🚀 两阶环境自适应工作流 (2-Tier Adaptive Routing)

Skill 在启动时依据 `SKILL.md §0.1` 的三级判定识别当前环境是否具备浏览器能力，并选择执行路径：

1. **Tier 1 (主模式 - 浏览器走查模式)**：
   - 当判定具备浏览器能力（内置浏览器子进程 / 浏览器 MCP / 三原语探测通过）时，**直接调用浏览器工具**完成走查、截图、批注与录屏，生成 HTML 检视报告。
2. **Tier 2 (降级模式 - 源码静态分析模式)**：
   - 当判定不具备浏览器能力时，平滑降级为静态代码分析，输出结构化 **Markdown** 报告，并在报告头部显式声明降级原因。
