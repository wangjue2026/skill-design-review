# 安全产品设计检视 (Design Review) Skill 包

本仓库旨在通过 AI 代理（Agent）标准化、专业化地对安全产品界面进行深度设计检视，确保设计方案不仅符合规范，更能体现产品的顶层体验愿景。

## 价值主张
- **专业深度**: 结合 10 年以上资深体验专家视角，识别隐藏的交互漏洞与心智模型偏差。
- **高维对齐**: 确保每一个设计细节都符合产品的“品牌灵魂”与“体验愿景”。
- **闭环产出**: 生成带有截图批注、问题定级（P2-P4）以及 To-Be 改进方案的专业 HTML 报告。
- **降本增效**: 通过自动化脚本实现毫秒级精准坐标定位与批注，告别手动绘图。

## 包含内容
- `SKILL.md`: **核心指令集**。定义了 AI Agent 的角色、四大检视维度执行逻辑、评分规则及输出格式要求。
- `references/`: **知识库**。
  - `01_体验目标制定.md`: 体验目标及宏大/务实双版本剧本制定规范。
  - `02_设计检视Checklist.md`: 检视子维度快速匹配指南与通用/特定场景 Checklist 准则。
  - `03_体验愿景.md`: 通用体验愿景基准与四大核心场景理念映射矩阵。
  - `04_HTML检视报告模板.html`: 报告生成模板。
  - `05_方案完备性检视Checklist.md`: 方案完备性与全状态矩阵（正常/空白/加载/报错/极端边界）专项 Checklists。
- `Reports/`: **产出根目录**。每个任务一个子目录（`Reports/<任务>_<日期>/`），内含报告 HTML、`assets/` 截图与批注图、`ledger.json` 过程账本、`ops/` 操作序列 —— 一次任务的所有产物收敛在一起，不再平铺在根目录；目录整体不进入版本控制。
- `scripts/`: **自动化工具箱**。
  - `auto_annotate.py`: 图片标注底层画笔，在浏览器走查模式下对截图进行框选、等级标签批注，落图至 `Reports/assets`。
  - `browser_runner.py`: **跨平台浏览器走查执行器**（零第三方依赖，纯标准库 + 本机已有 Chromium），通过 CDP 拉起独立窗口并执行 `setviewport / navigate / click / hover / type / scroll / key / eval / shot / wait`；交互走真实输入管线（`isTrusted=true`、有命中测试），并回传 `hit_self` / `blocked_by` 作为「按钮被遮挡」的直接证据。
  - `report_builder.py`: 通用报告生成器，读取问题 JSON（按 `configs/_template_issues.json` 空壳模板填写）并结合模板生成结构化 HTML 检视报告，内置评分计算、schema 校验、枚举白名单校验、**截图存在性校验**与准出自检；校验不通过以非零退出码拒绝出报告（`2` = 数据校验失败，`3` = 准出自检失败，`4` = 过程账本仍有未完成项），`--no-strict` 可临时放宽。
  - `ledger.py`: **过程账本工具**（防丢档）。把「证据 ↔ 结论」的绑定关系落盘到 `Reports/<任务>_<日期>/ledger.json`，支持 `init / add / apply / status / check / summary`；原子写 + 自动 `.bak`，中断后可按 `pending` 条目断点续跑；`check` 是有 pending 即非零退出的门禁。
  - `migrate_reports.py`: 一次性迁移脚本，把早期平铺在 `Reports/` 根下的报告（含 `_standalone` 版本）收进 `Reports/<报告名>/` 并把其引用的截图复制到同目录 `assets/`；支持 `--dry-run` 先看计划。
  - `configs/`: issues JSON 模板与历史样例（`_template_issues.json` 为纯空壳，不含任何示例数值）。

## 🎯 四大检视维度与执行顺序规程
- **维度选择式执行（默认分开）**：默认不自动全量检视，启动时输出维度选择卡片（说明各维度范围与意图）并给出初步判断，由用户确认要检视的维度；只有用户明确「全量」才同时执行全部 4 个维度。
- **执行顺序（以 `EXECUTION_FLOW.md` 为准，十趟制、串行、按证据类型切趟）**：
  **P0 建账与假设 → P1 静态扫描 → P2 全景快照 → P3 任务剧本走查 → P4 维度 2 初判 → P5 全状态取证 → P6 定向交互取证 → P7 维度 2 终判 → P8 收口对账 → P9 定级与报告**。
  - 每个检视项的证据类型由 `references/02` / `references/05` 条目末尾的 `[S]`（读代码）/ `[R]`（看渲染）/ `[I]`（动手操作）标签决定，**不再按维度预设采集方式**。
  - 浏览器只在 P2/P3/P5/P6 打开一次（同一会话）。
  - 每趟结束必须 `ledger.py apply` 登记账本；P9 出报告前 `ledger.py check` 必须通过，否则退出码 4 拒绝出报告。
- **报告生成**: 生成包含截图批注、严格 P2-P4 定级（最下方附带业务后果判定表）与四维定性结论的专业报告。

## 🛠️ 环境依赖与安装

- `browser_runner.py` 与 `report_builder.py` **零第三方依赖**：只需 Python 3.8+ 标准库，以及本机已存在的 Chromium 系浏览器（Chrome / Edge / Chromium / Chrome for Testing）。
- 仅图片批注脚本 `auto_annotate.py` 需要 Pillow：

   ```bash
   pip install -r requirements.txt   # 等价于 pip install pillow
   ```

## 🚀 两阶环境自适应工作流 (2-Tier Adaptive Routing)

Skill 在启动时依据 `SKILL.md §0.1` 的三级判定识别当前环境是否具备浏览器能力，并选择执行路径：

1. **Tier 1 (主模式 - 浏览器走查模式)**：
   - 当判定具备浏览器能力（内置浏览器子进程 / 浏览器 MCP / 三原语探测通过）时，先按 `SKILL.md §0.2` 的**优先级**探测走查执行器：**能直接拉起独立浏览器窗口就直接用（视口可控、可置于后台），拉不起就用环境自带的浏览器工具兜底，全程不引导用户安装任何东西**；随后完成走查、截图、批注与录屏，生成 HTML 检视报告。
2. **Tier 2 (降级模式 - 源码静态分析模式)**：
   - 当判定不具备浏览器能力时，平滑降级为静态代码分析，输出结构化 **Markdown** 报告，并在报告头部显式声明降级原因。
